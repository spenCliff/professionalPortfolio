Aero Optimisation Pipeline

Simulation CFD Bayesian Optimisation Python HPC

An automated pipeline that links parametric CAD, CFD, and Bayesian optimisation to explore a solar racecar's aero design space — 221 simulations run without touching a single one by hand.

Overview

[Add more context here if you'd like — e.g. what EKKO Solar Racing is, what the vehicle is built for, and what "mission energy" means for a solar car, for readers who aren't familiar.]

Solar racecar aero is a strange optimisation problem: you're not just chasing low drag, you're balancing it against solar panel area and the vehicle's pitch, since both affect how much energy the car actually has to spend and generate over a race. Running that trade-off by hand — tweak geometry, mesh, solve, wait, repeat — doesn't scale. This project was about building a pipeline that could explore that space on its own.

What I Did

The pipeline runs end to end without manual intervention: regenerate the CAD for a given design, mesh and solve it in CFD, pull out the results, and feed them back into an optimiser that picks the next design to try.

  • Set up a STAR-CCM+ simulation with a moving ground plane and rotating wheels, plus near-wall mesh control to properly resolve boundary layer behaviour.
  • Verified the setup with mesh and domain convergence studies, and benchmarked turbulence models against wind-tunnel correlation data to trust the baseline before optimising anything.
  • Built an automated Python pipeline: parametric CAD regeneration, HPC job submission over SSH/SCP, CFD meshing/solving/post-processing, and a database to track every trial.
  • Applied pitch-constrained Bayesian optimisation to minimise a mission-energy objective, combining CFD drag output with solar-area data.
  • Let it run — 221 simulations later, daily energy losses were down 37.6%.
